# Remaining original player dependencies for 0.17

## Scope and conclusion

This is a **dependency inventory and next-feature recommendation**, not a 0.17 implementation, release freeze, test result, SDK/HAP result, or device-compatibility claim. It starts from the actual **188 registration templates** in [ACTION_COVERAGE_016.md](ACTION_COVERAGE_016.md) and its [source ledger](tools/reference/action-coverage-016-source.json): **110 full within the declared portable contract, 23 partial, 55 unwired**. The baseline catalog had 155 IDs: 151 original concrete names and four OHOS additions. One registration expanded over several providers or target instances is still one template.

The useful remaining work is substantial player functionality: a real external-player source and clock, gesture-driven control, authorized script repositories, and complete output-target ownership/adapters. Most missing registrations are entry points into those dependencies. Creating labels, storing endpoint text, or exposing an existing helper does not close the feature.

**Recommended next major closed loop: DeoVR source → received timeline → authorized local script match → existing axis pipeline → explicitly connected/armed output, with actual remote controls and complete cancellation.** The retained original protocol has no correlated seek acknowledgement or server sample timestamp. The first implementation must revoke physical Arm before every remote seek; a send receipt or subsequently matching position cannot preserve Arm. The earlier [remote-source assessment](REMOTE_SOURCE_FEASIBILITY.md) reaches the same recommendation; this inventory rechecked the actual original reader/writer and current native-clock/output boundaries.

No production source, existing documentation, tests, SDK configuration, Git state, File recording, external player, network endpoint, credentials, or physical device was changed or exercised by this inventory. Only this new document and its companion [machine-readable inventory](tools/reference/remaining-original-dependencies-017.json) are deliverables. Original source hashes and registration text were checked statically; no application test was executed. The OHOS checkout is being integrated concurrently, so its evidence is a timestamped source snapshot, not a final freeze.

| 57, 58, 60, 61, 63, 64, 66, 67 | Output range Minimum/Maximum/Middle/Size Set and Offset for an explicitly identified existing target | Partial: original registrations belong to each `Name/InstanceIndex` target and are inherited by all eight original target classes. These candidates do **not** include four output range Drive rows, output endpoint or connection shortcuts, or the remote-player source adapters. They cannot promote any of the existing 23 partials automatically.

If all nine are genuinely wired and none of the inherited statuses changes, the conservative projection is **110 full / 32 partial / 46 unwired**. This is arithmetic on planned scope, not the final 0.17 count. Similarly, 164 eventual catalog IDs would mean **152 original concrete names + eight explicit-instance template-adapter IDs + four OHOS additions**. It must not be reported as 160 original concrete names. The final action audit must independently confirm actual catalog uniqueness, template mapping, owning runtime routes, argument contracts and effective tests.

The [output-range source audit](OUTPUT_RANGE_017_SOURCE_AUDIT.md) confirms why these commands need their own source-faithful implementation: offset limits can produce reversed raw ranges; effective WPF display coercion does not prove a provider write-back. The actual Middle Set and Size Set callbacks must be audited rather than replaced by formulas inferred from their names. Independently finite endpoints in 0..1 include reversed/equal ranges, but original legal editor inputs on degenerate raw states can also yield an endpoint outside 0..1; the bounded portable reducer refuses those complete edits. Missing target kinds, that known domain restriction and unexecuted WPF binding/lifetime prevent full classification. This document does not duplicate the scoped numeric oracle or claim its execution.

The [Looping Script source audit](LOOPING_SCRIPT_017_SOURCE_AUDIT.md) identifies additional real differences beyond filesystem scope. The planned route accepts an exact current catalog URI or full root-relative key, with no nested basename fallback, new root or dialog import. Native reads are capped at 2 MiB; the parser separately limits text to 8 MiB, axes to 32, aggregate actions to 100,000 and integer-millisecond time to 24 hours, requires finite 0..100 values and retains the last duplicate-time action, while the original keeps the first. Transactional retention after missing/unreadable/invalid input is also intentionally different: the original synchronous setter can clear Script or fail after partial mutation. These differences alone retain row 49 as partial even after the owning application transaction is proved. The original command does not search repositories; the restriction here is direct authorized-file/catalog scope, not an omitted repository call in that setter.

### External sources are more than endpoint settings

- [MediaSourceViewModel.cs:112–230](../Source/MultiFunPlayer/UI/Controls/ViewModels/MediaSourceViewModel.cs#L112) owns one current source, serializes connection changes, disconnects the old source before replacing it, and scans enabled sources. The three connection templates expand across DeoVR, Emby, HereSphere, Internal, Jellyfin, MPC-HC, MPV, OFS, Plex, PotPlayer, VLC and Whirligig. Merely mapping their IDs onto an Internal button does not cover the source family.
- [AbstractMediaSource.cs:54–124,176–191](../Source/MultiFunPlayer/MediaSource/AbstractMediaSource.cs#L54) owns asynchronous run/cancel/disconnect and accepts controls only while connected. Its common messages carry values but no source generation or sample timestamps ([Messages.cs:16–36](../Source/MultiFunPlayer/Common/Messages.cs#L16)). The OHOS physical-output contract requires that additional local ownership evidence.
- DeoVR and HereSphere use framed TCP JSON. HereSphere additionally handles `resource`/legacy `path` and `identifier` context. Whirligig is a passive line reader with no original outbound command writer or playback-rate observation. MPC-HC polls HTML variables and has whole-second seek formatting. Those distinctions must appear as capabilities, rather than enabling every common control indiscriminately. See [DeoVR](../Source/MultiFunPlayer/MediaSource/ViewModels/DeoVRMediaSource.cs#L94), [HereSphere](../Source/MultiFunPlayer/MediaSource/ViewModels/HereSphereMediaSource.cs#L93), [Whirligig](../Source/MultiFunPlayer/MediaSource/ViewModels/WhirligigMediaSource.cs#L69), and [MPC-HC](../Source/MultiFunPlayer/MediaSource/ViewModels/MpcMediaSource.cs#L86).
- OFS is a live editing integration: `funscript_change`, `funscript_remove`, `project_change` and `ReloadScripts:false` media changes are material dependencies, in addition to WebSocket timeline/control messages. An endpoint setter and player position parser alone omit the original streamed-script behavior ([OfsMediaSource.cs:90–206](../Source/MultiFunPlayer/MediaSource/ViewModels/OfsMediaSource.cs#L90)).
- Emby/Jellyfin need API-key-backed device discovery and current session selection. Plex needs a token, client discovery, client headers, XML timeline/metadata handling and command routing. Name selection is first exact ordinal match, followed by selection of the associated device/client ID. Refresh is guarded by disconnected/not-busy/credential state. Original protected settings use Windows `ProtectedData` and are not an OHOS secret store ([Emby:214–355](../Source/MultiFunPlayer/MediaSource/ViewModels/EmbyMediaSource.cs#L214), [Jellyfin:211–364](../Source/MultiFunPlayer/MediaSource/ViewModels/JellyfinMediaSource.cs#L211), [Plex:328–491](../Source/MultiFunPlayer/MediaSource/ViewModels/PlexMediaSource.cs#L328), [ProtectedStringUtils:20–56](../Source/MultiFunPlayer/Common/Utils/ProtectedStringUtils.cs#L20)). VLC also needs a password and HTTP Basic handling even though its only source-specific missing action is Endpoint Set ([VLC:25–67,258–275](../Source/MultiFunPlayer/MediaSource/ViewModels/VlcMediaSource.cs#L25)).
- MPV Arguments Set feeds optional `mpv.exe` process launch and a local named pipe, not a remote TCP client ([MpvMediaSource.cs:32–105](../Source/MultiFunPlayer/MediaSource/ViewModels/MpvMediaSource.cs#L32)). PotPlayer has no dedicated setting row in these 55 but remains a dependency of the shared connection templates: its implementation uses Windows processes, registry and `user32` window messages ([PotPlayer:30–63,290–314](../Source/MultiFunPlayer/MediaSource/ViewModels/PotPlayerMediaSource.cs#L30)). A Windows bridge would be a new architecture and deployment, requiring its own authorization and protocol.
- `Media::Path::Set` publishes a request to the connected source, rather than directly replacing a displayed path. Internal may find an existing playlist entry or construct a new playlist from that path; external sources differ in support. Actual incoming path changes also drive media identity and script repository work ([ScriptViewModel:535 onward,1424](../Source/MultiFunPlayer/UI/Controls/ViewModels/ScriptViewModel.cs#L535), [Internal:86–99](../Source/MultiFunPlayer/MediaSource/ViewModels/InternalMediaSource.cs#L86)). Remote paths are matching data and commands addressed to the remote player, never implicit local-file access permission.

### The nine Drive templates share a missing input subsystem

The original [IAxisInputGestureData](../Source/MultiFunPlayer/Input/IInputGestureData.cs#L12) carries `ValueOrDelta`, `DeltaTime`, absolute/relative mode and `ApplyTo`. [AxisDriveShortcut](../Source/MultiFunPlayer/Shortcut/AxisDriveShortcut.cs#L7) supports absolute, relative, signed-only and relative-joystick modes with inversion. [AxisOffsetShortcut](../Source/MultiFunPlayer/Shortcut/AxisOffsetShortcut.cs#L7) owns a repeat that is cancelled at zero and supplies its own delta time. These are not numeric constants attached to a keyboard press.

The original producers include Windows RawInput mouse/wheel, XInput gamepad polling and incoming TCode from supported output transports ([RawInputProcessor.cs](../Source/MultiFunPlayer/Input/RawInput/RawInputProcessor.cs#L124), [XInputProcessor.cs](../Source/MultiFunPlayer/Input/XInput/XInputProcessor.cs#L107), [TCodeInputProcessor.cs](../Source/MultiFunPlayer/Input/TCode/TCodeInputProcessor.cs#L13)). The current [ShortcutConfiguration.ts](entry/src/main/ets/input/ShortcutConfiguration.ts) explicitly provides local keyboard configuration, not those axis producers. A useful next gesture milestone must include an actual OHOS producer, calibration/dead zone where applicable, monotonic event timing, bounded rate/backpressure, focus/background and device-disconnect cancellation, mapping persistence, real dispatch and owning-session effects.

`Axis::Value::Drive` passes gesture delta time into the actual axis transition ([ScriptViewModel:1216 onward,1613–1615](../Source/MultiFunPlayer/UI/Controls/ViewModels/ScriptViewModel.cs#L1216)); replacing it with a fixed default transition loses behavior. Motion speed/range/blend Drive uses `ApplyTo`, while output range Drive invokes its own helpers. Any future TCode-input route must explicitly authorize that input channel; bytes received from a physical endpoint must not become arbitrary configuration or Arm commands. Reusing existing keyboard timers or output sockets is not proof that these nine routes exist.

### Output ownership and missing target adapters

[AbstractOutputTarget.cs:22–30,190–332](../Source/MultiFunPlayer/OutputTarget/AbstractOutputTarget.cs#L22) defines `Identifier = Name/InstanceIndex`, per-axis settings and the 14 shared auto-connect/range templates. [OutputTargetViewModel.cs:40–94,152–238](../Source/MultiFunPlayer/UI/Controls/ViewModels/OutputTargetViewModel.cs#L40) allocates instance indices, registers/unregisters each instance, serializes per-target connection, and scans auto-connect preferences. A saved selector must not silently retarget a removed instance to whichever target is currently selected or later reuses the same display name.

Current [OutputConfiguration.ts](entry/src/main/ets/settings/OutputConfiguration.ts) saves only TCP, UDP and WebSocket targets; [NativeOutputSession.ets](entry/src/main/ets/app/NativeOutputSession.ets) restores inert owners and tracks target/profile/edit generations. [NativeTransportFactory.ets:11–55](entry/src/main/ets/output/native/NativeTransportFactory.ets#L11) exposes those three network kinds with explicit connection and no device-execution ACK. The existing UI/network machinery does not itself wire rows 55/56, 72/75/76 or 80–82.

The missing target-specific settings conceal different implementation requirements:

- Buttplug Endpoint Set needs an actual Buttplug protocol client, device scan/add/remove lifecycle, per-device capability/settings mapping, supported command types, timing and stop handling. A raw WebSocket TCode transport is not that client ([ButtplugOutputTarget.cs:78–163,165 onward](../Source/MultiFunPlayer/OutputTarget/ViewModels/ButtplugOutputTarget.cs#L78)).
- PipeName Set belongs to a local `NamedPipeClientStream`, with fixed/polled TCode updates. There is no equivalent remote named pipe in the current OHOS code ([PipeOutputTarget.cs:27–120](../Source/MultiFunPlayer/OutputTarget/ViewModels/PipeOutputTarget.cs#L27)).
- SerialPort Set selects a discovered device ID, not arbitrary port text. Original discovery uses Windows WMI and includes serial settings plus received TCode input. OHOS device enumeration/permission/USB or serial transport must be designed and verified rather than inferred from the original API ([SerialOutputTarget.cs:34–125,246–259,319](../Source/MultiFunPlayer/OutputTarget/ViewModels/SerialOutputTarget.cs#L34)).
- The Handy ConnectionKey and SourceAxis need secure credential handling, authenticated HTTP, connected/firmware checks, device mode change, timing probes, polled source-axis control and the source-axis sync effect. The original uses a cloud API; neither connection setup nor a successful HTTP response is permission to move hardware or proof it moved ([TheHandyOutputTarget.cs:21–143,175–206](../Source/MultiFunPlayer/OutputTarget/ViewModels/TheHandyOutputTarget.cs#L21)). This inventory makes no current vendor API compatibility claim.
- File inherits the shared range/settings/connection registrations, but manual connection opens actual output writers and auto-connect returns without starting recording. Current separate recording support does not cover the original instance shortcut family. A new File connection route would require explicit recording destination/write authorization and lifecycle work, not a generic network connect alias ([FileOutputTarget.cs:13–107](../Source/MultiFunPlayer/OutputTarget/ViewModels/FileOutputTarget.cs#L13)). No File operation was performed here.

Original auto-connect flags are operational because the host scan consumes them. Saving a flag alone is not full original auto-connect parity. Future reconnection must preserve the application's explicit output-Arm policy; it must never restore a previously armed state merely because settings were loaded or a connection returned. Endpoint editing needs its own consistent live/disconnected policy, stale-draft checks and old-generation retirement. Closing a socket or recording writer must not fabricate remote/device completion.

### Repository completion is a separate major player capability

The six repository-primary partials are not waiting for another toggle or reload label. [LocalScriptRepository.cs:33–140](../Source/MultiFunPlayer/Script/Repository/ViewModels/LocalScriptRepository.cs#L33) searches the media directory plus configured script libraries and ZIPs, then applies ordered multi-/single-axis matching. [ScriptRepositoryManager.cs:28–77](../Source/MultiFunPlayer/Script/Repository/ScriptRepositoryManager.cs#L28) iterates enabled ordered repositories and merges results; [ScriptViewModel.cs:932–952](../Source/MultiFunPlayer/UI/Controls/ViewModels/ScriptViewModel.cs#L932) resolves link-priority versus searched axes around that result. Internal additional scripts specifically invokes the local repository for its current item ([InternalMediaSource.cs:285–311](../Source/MultiFunPlayer/MediaSource/ViewModels/InternalMediaSource.cs#L285)).

The retained external repositories include [Stash](../Source/MultiFunPlayer/Script/Repository/ViewModels/StashScriptRepository.cs#L26), with endpoint matching, scene lookup, optional API-key header, GraphQL metadata and local/direct-script matching; and [XBVR](../Source/MultiFunPlayer/Script/Repository/ViewModels/XBVRScriptRepository.cs#L21), with scene/file lookup, endpoint/path identity and local/DMS downloads. Current managed Download rescanning correctly rereads bytes, but does not implement those roots, identities, transports or merge scope. Expanding this capability requires explicit authorized roots/endpoints, secure credentials where applicable, bounded remote resources, privacy-preserving requests/logs, cancellation tied to current media/profile/link state and a declared failure/merge policy. A remote player's path must never silently authorize either local directory traversal or a credential-bearing request to a new host. This capability is deliberately outside the first DeoVR milestone, which can be useful with authorized local catalogs alone.

## Next major closed loop: DeoVR

### Why this is the next player feature

DeoVR covers both timeline observation and remote control without a Windows IPC dependency or a new credential store. It is a substantially more useful completion target than Debug Log or a collection of endpoint setters. HereSphere can follow after its resource/identifier semantics are implemented and verified. OFS is a valuable later live-editing feature but requires streamed script replacement/removal and a freshness policy for event-driven time updates; Whirligig cannot provide the same bidirectional control experience in the retained source. Authenticated servers and Windows-only players introduce additional architectures.

This ranking is an inference from the retained source and current port boundaries. It does not assert which current player versions accept remote clients or that a player runs on OHOS. The source-level facts below are directly rechecked:

1. [DeoVR:29–55](../Source/MultiFunPlayer/MediaSource/ViewModels/DeoVRMediaSource.cs#L29) connects to a configured TCP endpoint; the original default is loopback port 23554 and has a Windows-process check only for localhost.
2. [DeoVR:94–168](../Source/MultiFunPlayer/MediaSource/ViewModels/DeoVRMediaSource.cs#L94) reads a four-byte length and UTF-8 JSON; a nonblank `path` gates parsing. It receives playing state, seconds-based duration/position and rate, publishing changes. Zero/nonpositive length or missing path resets state. There is no server sample timestamp, command ID, seek-complete field or authentication handshake in that reader.
3. [DeoVR:173–224,264–270](../Source/MultiFunPlayer/MediaSource/ViewModels/DeoVRMediaSource.cs#L173) writes play/pause, seek, path and speed fields using the same framing and emits a four-zero-byte idle keepalive. Transport send completion is the only awaited write event; it is not a correlated media acknowledgement. The five-property serializer shape and byte-length framing need the existing source assessment's exact treatment.
4. [MediaClock.ts](entry/src/main/ets/core/MediaClock.ts) is specifically an AVPlayer observation model. [NativeVideoAdapter.ets:216–226](entry/src/main/ets/media/NativeVideoAdapter.ets#L216) ends native seeks from the actual callback and actual `player.currentTime`. [PlaybackSessionCore.ts](entry/src/main/ets/core/PlaybackSessionCore.ts) binds native source generation, observation and seek sequence, and enforces a 750 ms playing-clock freshness budget. Remote packets cannot legitimately impersonate those native callbacks.

### Required reachable product path

The milestone must include all of the following, in one application flow:

- A real DeoVR entry in source selection with bounded endpoint editing, explicit Connect/Disconnect, connection/readiness/observed playback state and useful redacted diagnostics.
- A dedicated source-native port or genuinely neutral socket abstraction. Existing output adapters require output configuration and output admission; a remote player must not be registered as a physical target to borrow TCP access.
- A bounded incremental framing codec that handles fragmented headers/payloads and coalesced frames, explicit little-endian length, UTF-8 byte counts, reset, malformed input and bounded work per event. Original nonpositive-length behavior versus any stricter negative/oversized-length rejection must be documented.
- An observed remote timeline with protocol/endpoint identity, connection generation, resource generation, observation sequence, local monotonic receive time and field validity. Connected, source-ready, processing-enabled, output-connected and output-armed must remain different states.
- Authorized local catalog/script binding for the actual remote resource, including ambiguity/no-match/invalid-script states. Never open or fetch a Windows, UNC, URL or scene path merely because a packet contains it. Resource replacement immediately retires old scripts/clock; async reads carry resource ownership.
- Play/Pause/Seek/Rate controls routed to the selected source, with displayed state taken from observation. Path changes can be included only with an explicit remote-command contract and authorized destination. Unsupported operations remain disabled. Local Stop closes processing/output gates; local socket close does not prove the remote player paused.
- Existing axis processing, timing and output admission, without a packet callback writing physical bytes directly. Source packets never create Connect or Arm intent. Useful preview is possible with no physical target connected.

Implementing only the codec or endpoint action does not meet this milestone. Adding a single source's names also cannot make the twelve-source connection/auto-connect registration templates fully covered.

### Clock, ACK and discontinuity requirements

**There is no supported seek-preserving-Arm evidence in this retained protocol.** Before sending a remote seek, including an AB-loop or AutoSkip seek, synchronously invalidate pending output candidates and revoke physical Arm. Do not call native `endSeek`, invent a seek sequence, preserve the existing same-source keep-arm transaction, or confirm a target because a send succeeded or an observed position is nearby. Later valid observations may restore preview/processing readiness; physical output needs a fresh explicit Arm against an eligible current frame.

If continuous armed AB looping is a product requirement, the milestone is blocked on separately verified stronger acknowledgement/observation semantics. The first release must either disclose seek-induced disarm or disable automatic remote-seek controls; it cannot hide that limitation by manufacturing an ACK.

Local receive time measures age since receipt, not server sampling age or network latency. A valid packet containing only a path/state does not refresh the position clock. Outbound keepalive, a UI repaint and rereading an old snapshot are not observations. Repeated unchanged positions while reportedly playing require an explicit stall policy. Missing initial duration/state/rate/time must not default into physical-output readiness. The current 750 ms budget is application policy, not a guarantee of DeoVR's update interval; set and test a conservative explicit remote policy without silently loosening the native one.

Reset, path change, reconnect, endpoint replacement and detected discontinuity retire the previous output authorization. Equal path strings do not prove equal playback instances; same-path reload without a distinguishing wire event cannot be perfectly identified from these fields. TCP ordering does not correlate an observation to an outbound seek, especially when earlier data was already queued. These are evidence limits to disclose, not conditions to infer away.

### Cancellation, lifecycle and permissions

- Retire the current source generation synchronously before awaiting DNS/connect/write/close, switching source, replacing endpoint, entering background, closing the page/Ability or changing resource. Late callbacks, delayed command sends and script loads from old owners must be inert. Bound parser memory and command queues. An uncertain write must not be blindly replayed; an unconfirmed close must remain quarantined.
- Initial source bytes may arrive before the connect promise and socket-option setup finish. Current [output TCP receive handling](entry/src/main/ets/output/native/NativeTcpTransport.ets#L188) uses an output-readiness gate, set after connect while [native connect also awaits socket options](entry/src/main/ets/output/native/NativeTcpTransport.ets#L365); a source adapter needs bounded early-byte handling so the bootstrap state is not discarded. Both old and new callback races need explicit coverage.
- [module.json5:12](entry/src/main/module.json5#L12) already declares `ohos.permission.INTERNET`; the native network factory checks actual SysCap. This establishes a code permission declaration, not connectivity, server access or a real-device pass. Any additional OS permission or persistent credential/bridge setup is a separate explicit user-controlled step.
- Use the user's explicitly supplied reachable player endpoint. `localhost` on an OHOS device refers to that device, not a Windows PC. Do not scan the LAN, guess emulator host aliases, enable a server, install a bridge or change firewall/security settings as a side effect of this implementation.
- The retained DeoVR path has no authentication and uses plain TCP. Use an explicitly trusted endpoint and disclose that limitation. Keep private media paths, raw JSON, signed URLs and secret-bearing endpoints out of logs/config exports. This milestone needs no real credentials; authenticated-source work must use a separately approved secure credential-entry/storage path, never copied Windows ciphertext or plaintext fallback.
- Source connection is not output connection or Arm permission. Physical output, real network/player validation and File recording remain separately authorized activities; none is required to execute local in-memory verification of the source milestone.

### Evidence needed to call that milestone complete

1. **Codec/original behavior:** real production codec exercised using in-memory packets, split/coalesced frames, UTF-8, null/optional fields, reset, invalid/nonfinite values, limits and actual outbound shapes. Retained C# reader/writer comparison where harnessable; limitations stated.
2. **Source owner and clock:** early receive before connect settles; valid/partial snapshots; stale/unchanged time; reset/path/reconnect; backward/invalid monotonic clock; slow or failed DNS/connect/write/close; no stale callback, command replay or synthetic observation.
3. **Real session/output path:** production source adapter plus actual session core, coordinator and target collection with MemoryTransport only. Verify authorized normal playback, fixed/polled selection, provenance and exact axis scope, explicit Arm, seek revocation, pause/Stop/background/resource replacement, stale candidate/receipt rejection and recovery without automatic rearm.
4. **Reachable controls/library:** actual Index/component route for selection and commands; correct disabled capabilities; authorized/ambiguous script selection; no remote-file open; cancellation of old loads; source switching and Ability teardown.
5. **Regression and SDK:** scoped and aggregate regressions plus official SDK/HAP compilation of the reachable adapter and UI. A source-only helper pass or an unreachable class is insufficient.
6. **Separately authorized real-device gates:** actual OHOS network reachability and permissions; exact player version, wire shapes/update cadence, controls, latency/stalls, suspend/resume and cleanup. Physical output is an additional gate. Mock/build success cannot establish actual remote synchronization, acknowledged remote command completion or hardware execution.

These are future acceptance requirements. This dependency inventory executed none of them.
