### Endpoint and connection semantics

The original Endpoint callback invokes NetUtils.TryParseEndpoint and assigns on success. Its optional InterNetwork/InterNetworkV6/Unspecified prefix can bypass ordinary host-type checking, and it has no connected-only guard. Current action accepts the prefix as text but always validates the actual raw host and derives transport family from it. Host length is 1..253, DNS labels are strict, ports are integer 1..65535; URLs, credentials, paths, zones, trailing-dot DNS and original port-zero/prefix-bypass cases are excluded. Unchanged validated preferences succeed inertly. Changed preferences retire active/unconfirmed DeoVR ownership and stop output before commit; failed close prevents replacement. This intentional behavior differs from original property-only mutation while connected.

Only Internal and DeoVR implement the three connection templates. The ten absent expansions are Emby, HereSphere, Jellyfin, MPC-HC, MPV, OFS, Plex, PotPlayer, VLC and Whirligig. Connection is explicit and foreground/current-owner guarded. Internal still depends on managed local scripts; DeoVR requires an existing managed catalog, a safe endpoint and confirmed retirement of old media ownership. Restored selection/endpoint/shortcut text is inert. Source Connect never connects or Arms output. DeoVR AutoConnect actions and the original automatic host scan receive no credit.

### Path, received clock, scripts and output

Media::Path::Set sends remote metadata; it does not open that string locally or install an optimistic path, clock or script. After a real received path revision, Index.matchDeoVrScripts derives a bounded basename hint and searches only existing authorized Download/managed-library catalog entries. Reads use their concrete owned URIs. Source/resource/request/profile/catalog/foreground checks reject stale completion. Original path modifiers, source-directory/resource-equality behavior, unrestricted local repository search and WPF/Windows path lifetime remain distinct and partial.

The complete original chain is documented in [DeoVR source audit](DEOVR_018_SOURCE_AUDIT.md): exact registered callback → host/base source ownership → reader/writer/global serializer → MediaPathChangedMessage → resource builder/modifiers → repository matching → common media controls/settings and WPF bindings. Current markers cover Index, DeoVrSession, NativeDeoVrTransport, DeoVrMediaSource, protocol codec, RemoteMediaClock, PlaybackSessionCore, resource search/read and the real output owner.

**There is no correlated seek ACK, server sample timestamp, command ID or resource-instance ID in the retained protocol.** Every remote seek, including chapter/bookmark, gap skip, AB loop and automatic skip, goes through the disarming remote route. Path changes also stop output before send. A local write receipt or nearby received position cannot preserve or restore Arm, and no native AVPlayer seek-complete transition is fabricated. Fresh received current-resource evidence and an explicit re-Arm remain required. Complete unchanged-position packets refresh receipt age but cannot extend motion indefinitely; partial/malformed packets, snapshots and command completions cannot manufacture position observations. Actual sockets, deployed player cadence and physical timing remain separate unexecuted gates.
