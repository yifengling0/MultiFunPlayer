# Native recording filesystem contract

The ArkTS trusted adapter alone supplies an absolute directory obtained from the system Download/app namespace flow. The native API is not a general user-path filesystem interface. No UI setting, imported recording, filename template, network response, or command may select its root. prepareRoot opens the trusted system app-Download parent without assuming its UID/mode, then uses mkdirat to create a dedicated recordings child with mode 0700. The child must belong to the current app UID and prohibit group/world writes. Existing owned 0755 directories are intentionally accepted; exact 0700 is not required for an existing child. File content is created with mode 0600. Existing directories are never chmodded or chowned. Each path component is opened with O_DIRECTORY | O_NOFOLLOW; symlink aliases, dot components, and noncanonical repeated separators fail closed. Platform directory/ownership behavior still requires a physical-device test; do not weaken checks when a provider returns a URI or an unsupported path.

Each create pins a directory descriptor, exclusively creates a 0600 basename.partial via openat(O_EXCL | O_NOFOLLOW), and returns a 128-bit random capability token. Caller-supplied file names accept only bounded ASCII alphanumerics, underscore, dash, and dots; traversal, slash, control characters, and unsupported suffixes are rejected. A preflight final existence test only improves diagnostics: correctness uses O_EXCL for partial creation and linkat for atomic no-replace final publication. No check-then-overwriting-open or overwrite rename exists.

All filesystem calls execute in NAPI asynchronous work. A call copies at most 256 KiB, with at most 64 jobs/64 open capabilities. The ArkTS queue must await operations on each token, enforce total recording limits, and stop on failures. Native writes loop through short writes and EINTR. A failed write/fsync/close taints the file. Close consumes the descriptor exactly once even on EINTR; a token retains directory/inode metadata until release/abort. Flush then close is mandatory before publish.

Finalization uses linkat followed by directory fsync. Successful publication also retains the .partial hard-link alias as a recovery file; no automatic alias cleanup is performed. This is a no-overwrite atomic publication of ONE file, not a multi-axis transaction. Error code 117 (EUCLEAN) means the final was published but subsequent directory durability sync failed; the UI must include that file in its partial-publication recovery manifest. Failure before link leaves the partial. Abort closes and forgets a capability and deliberately preserves all partials and finals. It never removes a previously published output. Success intentionally leaves two names for the same content; the alias is not a separate snapshot. Recover by inspecting both without overwriting anything. Cleanup, if desired, is a separate user-managed action.

The root is an app-owned, non-shared writable namespace. Other code in the same UID must not mutate names inside it concurrently; POSIX path-based linkat cannot defend against a hostile same-UID mutator between identity checks. This implementation never unlinks recording files, including recovery aliases, so it cannot delete a replacement through an automatic cleanup path. Inode checks detect substitution before publication; no external directory is traversed or file target followed. There are no raw Linux syscalls or unverified renameat2 assumptions. Unsupported hard links or directory fsync fail visibly; there is no unsafe fallback.

Host test: ohos/tools/check-recording-native.sh. Optional OHOS_NATIVE_SDK points to the official native SDK to compile/link ARM64 and x86_64. Host tests use disposable /tmp directories and link-time syscall fault injection only. SDK build success is not a device runtime/storage durability claim. Real phone/pad/PC coverage requires HAP install, SDK Download path/permissions, filesystem hardlink support, lifecycle, and disk-full testing.
