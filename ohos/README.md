# MultiFunPlayer for OHOS — 0.1 simulation preview

Native ArkTS/ArkUI port in progress. Original Windows application is unchanged.
Upstream baseline: `36c08fbb99ac9398a63ff1cca1bbf68cd2228a94`.

## Included

- Stage app declares phone, tablet and 2-in-1 PC support.
- Compact portrait tabs, phone-landscape two-column layout, wide-window dashboard.
- Native document picker, read-only local UTF-8 `.funscript` / JSON import (2 MiB UI limit).
- Single/multi-axis keyframes, bounded validation, linear interpolation, timeline and axis monitor.
- Synthetic demonstration; playback/pause/seek/stop and simulator disconnect.
- Foreground lifecycle safety gate, no automatic resume after background/disconnect.
- 48 vp or larger principal buttons, persistent transport controls, monotonic elapsed clock.

This is an early interface and core milestone, not full feature or visual parity with the desktop application. PC means HarmonyOS PC. Window layout is driven by available width/height, including split-screen and resizing, rather than a device-name check.

## Safety and limitations

There is **no physical output transport** in this version: no network, USB, serial or Bluetooth commands. Axis bars are preview values, not proof of emitted commands. Stop/interruptions close the simulator gate. Physical-device safety and hardware watchdog behavior remain future work.

Not implemented: video playback, remote media-player control, TCP/UDP/WebSocket output, PCHIP/makima, offsets/speed editing, axis limits/soft-start, C# plugins, Windows named pipes, USB drivers, chapters/bookmarks/config migration. Metadata fields such as `inverted`, `range` and `version` are not applied. The parser is intentionally stricter than upstream: invalid/out-of-range points are rejected instead of clamped/skipped. Preview graph decimates large datasets for drawing; core interpolation uses all validated points.

The file picker may show all document types; selecting a file does not bypass JSON and size validation. Imports never upload files. Cancel/failure leaves playback paused. An empty script can be previewed but cannot play. Reading and JSON parsing happen on the UI flow; larger-file worker parsing is future work.

## Build

Use an official HarmonyOS SDK/DevEco command-line-tools installation with API26 and JDK21. Configuration targets SDK26 and declares minimum compatible version 6.0.0(API20); this declaration is not evidence of testing on API20 devices. No SDK, credentials or signing material is included.

```sh
export HARMONY_TOOLS_HOME=/path/to/command-line-tools
export JAVA_HOME=/path/to/jdk-21
bash ohos/tools/build.sh
```

For pure core tests only, Node24 supports the TypeScript source directly:

```sh
cd ohos
node --test tests/core.test.mjs
```

The build produces `entry/build/default/outputs/default/entry-default-unsigned.hap`. It is **unsigned**, not an install-ready release. Signing, device pairing and installation require the appropriate account/device authorization. No signing keys or persistent credentials are generated by the build script. GitHub CI covers pure core tests only; it does not silently claim an SDK/HAP build.

## Validation still required

Real phone portrait/landscape, tablet split-screen, PC free-window sizing; repeated import/cancel; invalid/large files; app background/foreground during playback/import; navigation and slider gestures; large fonts/safe areas/software keyboard; supported OS/device combinations. Build checks do not replace UI/device testing.
