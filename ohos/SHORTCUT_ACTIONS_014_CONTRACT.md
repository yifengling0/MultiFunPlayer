# 0.14 command and managed reload contract

This stage extends the immutable 0.13 baseline; planned commands are not counted as implemented until their catalog, real handler, owning dependency, tests and SDK reachability are verified. Version target: 0.14.0 / code 15. Git publication and File recording remain paused; no physical endpoint is contacted.

## Motion and named commands

- Reuse the four existing Motion configurations, providers and original numeric algorithms. Add the 16 source scalar/enum/Reset registration templates, with exact provider applicability and runtime expansion. Drive, point-array and arbitrary script-path commands are outside this slice.
- The action targets an enabled active axis with the same captured profile lifetime as existing Axis actions. Explicit missing/disabled axes do not fall back. Configuration is cloned and validated before publication; configuration cannot manufacture a frame, clock observation or output Arm.
- Property changes preserve the original provider RequestSync behavior and runtime phase. Custom Curve UI Reset and shortcut Reset have different source contracts: UI Reset does not request sync; shortcut has an explicit Request sync boolean defaulting to true, requests sync first when set, then resets state. Repeated Reset still executes. Loaded-view binding effects must be audited in addition to the registration callback.
- Internal PlayByName selects the first matching current queue Name or FullName using original ordinal-ignore-case comparison, then uses the existing ordered PlayByIndex/load/seek path. Name text is a match key only, never converted into an I/O path. Connection/readiness and current authorized Download identity remain mandatory.
- Shortcut Enabled selects the first exact ordinal mapping name. A dedicated enabled mutation persists only that setting without reconstructing runtime entries or cancelling the currently owned batch/delayed/repeat actions. Disabled means future gesture updates are ignored, not emergency cancellation. Stop/F12, focus/IME, background, source/context retirement and ordinary UI configuration edits retain their cancellation policy. No queue, pressed state or timer is restored from storage.

## Real managed script reload

- Replace cached-only Reload/Link dependency paths with actual bounded reads of current authorized Download resources, without adding folder or single-video import. Current matching, ZIP priority, parser strictness and cumulative budgets remain in force.
- Reload uses the actual current media/source identity and captured profile, library and command lifetimes. It must not restart a video, advance its clock, invent a seek completion, reset all Motion phases or silently select a different source.
- Preserve original ResetSync-before-search order, LockScript protection, linked-axis propagation and resource reference identity. A freshly read same-content resource is still a new resource; a locked existing resource stays the same object.
- While an asynchronous replacement is pending, stale sources cannot dispatch. Cancel/error/source replacement/Stop/background cannot publish a delayed resource or resume physical Arm. Commit only an owned current result, then wait for a genuine new frame. Whether an earlier arm can survive a successful reload must be explicitly bound to existing pending-frame policy, never acquired automatically.
- Missing, malformed, removed or unreadable resources produce honest status and safe resource handling; they must not masquerade as a successful cached reload. Disabled saved axis configuration remains preserved.

## Acceptance

Source registration plus property setter/notification/loaded binding evidence; pure bounds/coercion tests; actual Index keyboard/touch paths; self/other Enabled and pending-timer cancellation boundaries; Motion scalar/Reset numerical/provenance checks; real mocked bounded I/O reload/Lock/link/late-result tests; current mobile control reachability; full actual-.NET aggregate and official clean SDK HAP with immutable before/after production hashes and independent archive review. No hardware, visual or physical-device acknowledgement claim follows from mocks.

## Implemented managed-reload transaction

- Index reindexes only the already prepared `libraryRoot`, bounded by the existing 1,000-entry/four-level scanner. A new file under that same root can be discovered. It does not call Download preparation, select a new root, or turn a shortcut name into a URI. Internal association and native-video identity are resolved from the new catalog; ordinary Refresh remains the explicit source-closing operation.
- Priority-only target sets skip repository I/O. Otherwise fresh candidates use the existing matching/ZIP/multi-axis parser and 64-candidate, 8 MiB text, cumulative-action limits. No-match is different from a failed read: a real no-match runs original fallback/priority linking and retains ordinary scripts. Read/parse/ZIP errors, incomplete scans or warnings abort the replacement, retain old bindings as a failed transaction and disarm targets with an explicit diagnostic.
- Begin requests sync before I/O, closes current dispatch and preserves only already-owned target arm intent through the established pending-frame queue-clearing policy. Media observations and Motion ticking continue. Commit adopts freshly parsed identities and closes dispatch until another actual pipeline tick. No completion callback publishes a frame or arms a new target.
- Cancellation advances the session epoch while preserving numeric state/provider phase, so even a coordinator that misses the intermediate cancellation snapshot cannot reuse a previous arm. Stop, background, focus/IME, ordinary mapping/config changes, source/catalog/root replacement and explicit cancellation prevent stale results from committing. Output target edits/disconnect/reconnect independently revoke that target's arm; unaffected pre-existing targets can resume only after successful current commit and a valid new frame.
- The axis settings section has a full-width reload/cancel control (48 vp on touch devices), status and the same dispatcher as keyboard/touch action groups. It does not add a folder or single-video import option.

## Explicit source/runtime boundaries

The 150-entry concrete catalog includes 146 upstream-named actions expanded from 128 of 188 source templates plus four OHOS additions. These counts are separate from completeness. Loaded WPF RangeSlider coercion, Custom Curve Duration canvas pruning, Octaves-bound-editor coercion, original unbounded/null names, all-repository search and other unimplemented input families are recorded in the per-template 0.14 ledger. Source inspection and headless tests do not establish Windows WPF scheduling or physical keyboard/touch behavior.
