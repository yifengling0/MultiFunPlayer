## What is actually wired in 0.17

### Managed Looping Script, original row 49

Touch and keyboard action dispatch reach Index.reloadManagedLoopingScript → exact current authorized Download catalog resolution → LibraryFiles.readScript of the catalog-owned URI → direct Looping parser → current session token → configuration and real resource installation. The token checks source/configuration/control/profile/epoch ownership; the host also checks root/catalog/library request, foreground/view, writable state and shortcut lease. The same URI or relative key executes a fresh read, installs a fresh resource generation, resets phase/index and requests source sync. Provider numeric Value and the manager cache remain until a real update; no fabricated clock/frame or Arm is created.

Only a complete current catalog URI or complete root-relative key is accepted. Nested basename, case-folded match, arbitrary path, root concatenation, companion-axis filename remapping and new directory/video imports are absent. Duplicate/ambiguous catalog identities fail. Failure/cancellation retains the previous resource/configuration and revokes output eligibility; late work cannot commit after Stop/background/source/profile/configuration/catalog or command ownership changes. Restore has its own guarded path and cannot use saved text as authorization.

**Still partial:** managed access/read/parser budgets, stricter malformed/empty handling, last-duplicate versus original first-duplicate parsing and transactional failure semantics differ from the original FileInfo setter. Exact Windows/Fody notification and exception order is unexecuted. The existing common dispatcher also resolves a blank targetAxis to its captured selected axis; original null DeviceAxis is a no-op. This convention is disclosed rather than advertised as null-axis parity. See [source audit](LOOPING_SCRIPT_017_SOURCE_AUDIT.md).

### Eight output range template aliases, original rows 57–67 excluding Drive

The same touch/keyboard dispatcher resolves one required saved outputTargetId and its captured live generation, applies the exact eight callback formulas to one current axis, then commits through NativeOutputSession.updateRanges → OutputCoordinator.updateRanges → OutputSession.updateRanges. There is no implicit current-output fallback, all-target broadcast or new connection/Arm. Removed/recreated targets cannot inherit queued commands by reusing the saved ID. Unrelated unapplied draft fields prevent connected live edits from leaking into the applied target; disconnected edits save preferences only. Axis Enabled, endpoint, protocol, update mode, profile and paused permissions are unchanged.

- Minimum/Maximum Set/Offset retain independent ClampSafe bounds. Middle Set subtracts **half width**, not current midpoint. Size Set enters **OffsetSize**, including its .01 size clamp. Independently crossed/equal limits are evaluated, not rejected by an invented ordering rule.
- Every final endpoint must remain finite in **0..1**. Reversed and equal endpoints are legal, preserved and shown explicitly. Some legal original editor inputs on degenerate raw states generate out-of-domain endpoints; those complete edits are refused without silent sorting/clamping.
- A changed range invalidates old candidates, fixed/polled queues and receipt authority, and requires a **genuinely newer source frame**. Successful unquantized mapped dirty history is preserved. Polled mode waits for actual source events; changing a range cannot fabricate one.
- Only existing eligible Arm intent survives unchanged source/profile/scope/permissions. Stop, background, disconnect, faults, cancellation and stale owners revoke it; an unarmed target remains unarmed. Already submitted bytes cannot be recalled. Invalidated partial stream writes close conservatively; late completion cannot update the new range's successful dirty cache or replay old work.

**Still partial:** only TCP/UDP/WebSocket are supported versus eight original target classes; static aliases are not dynamic Name/InstanceIndex imports; finite normalized domain and original raw settings differ; blank-axis captured-selection dispatch differs from original null no-op; Windows loaded-control/lifetime and physical scheduling remain unexecuted. Original Drive, output endpoint/connection/auto-connect and unsupported target actions receive no credit. See [source audit](OUTPUT_RANGE_017_SOURCE_AUDIT.md) and [contract](SHORTCUT_ACTIONS_017_CONTRACT.md).
