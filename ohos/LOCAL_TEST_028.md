# 0.28 local continuous-input checks

Use a user-owned compatible device. This package is unsigned and needs official local signing/deployment. These steps verify native event delivery; Linux mocks and the C# numerical oracle do not prove touch, wheel, old-runtime or hardware behavior. No output target is needed for the initial checks.

1. Open 设置 → 输入 → 本地连续输入 (advanced fold). Add a mapping, choose touch or mouse, X/Y, Drive and an explicit enabled axis. Begin with MotionProviderBlend and Absolute so the real setting change is visible without physical output. Confirm edited numeric/text fields explicitly; blur must not save.
2. Press 明确启用本地接收. Move inside the local surface with a single finger or held left mouse button according to the selected source. Check Value/Delta/status and the selected axis's real blend. Converted mouse/touch delivery must not double-apply. A normal release stops that contact but allows a fresh contact while reception remains enabled.
3. Check the five Drive modes and Invert. Positive/negative filtering is applied before inversion. RelativeJoystick accepts only motion away from center on its corresponding half; it is not an automatic spring-center or permanent joystick loop.
4. Choose independent Offset and a low Speed. Nonzero live contact first applies after100ms, then every100ms; release/zero/Cancel stops it. Hover outside, leaving the region, resizing/rotating, switching tool, opening a text editor/modal, losing window focus, background or Stop must retire reception. Returning must require explicit enable and a new contact. Ordinary window blur must not independently stop already-running media.
5. Wheel only supports immediate Drive. Choose wheel X/Y and the explicitly labelled local calibration span. Values are native axis samples, not claimed Windows120-count or hardware-calibrated vp. Confirm normal outer scrolling works when reception is disabled or the mapping does not match. No wheel event can start Offset repeat.
6. Mapping preferences may persist; capture, pointer, deadlines and reception must not. Restart/restore must not play, connect, preview or Arm. Disabled/read-only/recovery/changed profile or removed output gives clear rejection, never silently redirects another target.
7. For local manual-preview testing, start a fresh explicit manual preview first. A separately connected user-approved fixed target needs its own paused-manual permission and explicit Arm-wait; it must show waiting/no output until a real Value Transition tick. Unpermitted/polled/other axes stay closed. Stop revokes input and Arm. Merely touching a Value mapping must never start preview or Arm.
8. Existing edge: Value applied and ticked while stopped leaves an old-epoch held scalar; later idle preview cannot authorize it for Arm-wait. Use the existing explicit runtime-rebuild recovery, then start preview and explicitly Arm. No automatic reset is performed.
9. Range Drive only lists actual TCP/UDP/WebSocket target identities. Minimum/Maximum/Middle/Size alter the selected target through the original-backed range transaction. Test with a local receiver first: range edits clear old pending data, preserve only already explicit Arm intent, and wait for a real current frame. Serial range Drive remains outside this increment.

Keep the previous0.25/0.27 layout/material checks. Capture device model, OS/API, display size/orientation, actual touch/mouse/wheel type and status text for any mismatch. Do not report physical motion or ACK based solely on an application counter.
