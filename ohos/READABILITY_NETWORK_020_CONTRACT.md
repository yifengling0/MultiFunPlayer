# 0.20 readability and socket evidence contract

The user's current priority is readable controls/text, restrained luminous buttons, a visually integrated title bar, and genuine TCP/UDP connectivity. This stage improves practical use rather than expanding the original action count.0.19 remains immutable.

## Audited baseline

Index used9-vp axis status,10-vp source state,11–14-vp timeline/header/body text,34-vp automatically compact PC controls and48-vp touch controls. Its48-vp separate title banner and84-vp video control reservation cannot simply receive larger fonts without adjusting geometry. Shared fields and component rows also have fixed narrow widths and label truncation. These are production source findings; no native screen capture has been claimed.

## Presentation

- All device classes default to readable. General.uiDensity='readable'|'compact' is a persisted additive preference; old settings restore readable. Explicit compact changes spacing/body18→16 only, with controls at least52vp in either mode.
- Titles at least22vp, body16–18, helper/status at least14. Buttons use subtle edge highlight, layered off-white/slate surfaces, clear dark text, restrained accent and genuine pressed feedback. Danger/Stop uses a distinct contrasting treatment; information is never encoded by color alone.
- Long labels/status/errors must wrap or have an explicit full-text path. Narrow panes stack fields; lists and toolbars can scroll. Parent workspace remains the scroll owner. Font/geometry changes do not alter callbacks, source/target identity, focus/IME/Stop, numeric algorithms, native Surface ownership or output authorization.
- A fixed global Stop is72×52vp, never disabled and outside all workspace scrolling. It calls the existing hard-stop path. Below320vp the integrated header uses two rows/128vp; otherwise72vp. Fullscreen and blocking error layers retain their own visible52vp Stop. It does not rely on F12, a selected target or a scrolled section.
- The integrated title uses the app's safe content area and existing verified window presentation capabilities. It does not imply universal system fullscreen. Video controls remain outside the native surface; narrow landscape may omit duplicate seek row, with timeline still reachable in settings.
- Validation uses production token/layout-derived static geometry, contrast, controller tests and official SDK compilation. A runnable browser approximation covers phone portrait/landscape, tablet and PC/narrow windows. Rendering was blocked by the permitted environment and those routes were stopped; no screenshots or completed visual inspection exist. Native visual/touch/IME/font-scale acceptance remains unverified.

## Network evidence

1. Linux loopback uses the actual shared encoder/coordinator/session and production native transport classes with an injected NativeEnvironment backed by real Node net/dgram sockets. It binds/connects only127.0.0.1 ephemeral ports, verifies bytes/receive/gates/close/cancellation and labels this Node-bridge evidence. It is not an execution of OHOS SDK networking.
2. A separate explicit one-shot native diagnostic uses production transports and a dedicated test receiver. It sends a bounded non-motion MFP_DIAG challenge with a fresh128-bit nonce and admits only an exact current echo. No Arm, TCode motion or restored setting starts it. Exact echo proves round-trip bytes to that receiver, not physical device execution.
3. UI requires a known endpoint and explicit confirmation that it runs the supplied diagnostic receiver. All normal output targets must be disconnected/unarmed/notbusy with confirmed closure. While diagnostic owns the channel, every normal Connect/Arm route is blocked, not just disabled visually. Media preview can continue independently.
4. Request/generation/endpoint/foreground ownership is immutable during a run. Stop/F12/background/page teardown cancels immediately, then awaits exact-generation close. Three-second overall timeout, bounded buffers/logs and close quarantine prevent late success/reuse. Nonce/payload/credentials are not stored in ordinary settings/logs.
5. Receiver scripts default toloopback; LAN binding requires an explicit argument and displays its scope. No user endpoint was provided, so development never contacts an unknown player/device. Real OHOS backend evidence requires the user's device and this test receiver; Linux success is not labeled native-device success.

## Boundaries

No Git publication, signing, installation, unknown physical-device connection or File recording review/release. Prior original numeric/lifecycle and actual C# oracles remain regression requirements. Full aggregate, official clean build, immutable input/source/HAP hashes and independent review precede local delivery.
