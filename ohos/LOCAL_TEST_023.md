# 0.23 用户本地串口验收

本包未签名。使用官方HarmonyOS SDK26签名部署到自己的设备；源码/完整MIT许可和mock证据随恢复包。没有实机验证，下面为用户执行流程，不是已经执行的结果。

## 先只读

1. 不接运动负载或先按设备自身说明使其安全。打开App应只有媒体预览，输出全部未Arm。恢复设置不应出现USB权限弹窗。
2. 添加串口目标，选USB CH340/341实验后端，插入自己的设备并点刷新。记录候选VID/PID；没有候选时可截系统USB信息，不要把别的vendor设备强套CH后端。
3. 断开全部输出，选择候选，点授权并只读识别。仅由这个点击申请USB权限；可拒绝一次，确认不会连续弹窗。再明确重试。成功后复制报告或截图，报告不含路径/串号；该流程不初始化UART、不发送轴命令。
4. 测试等待中Stop/后台/换目标；返回不应发布旧成功报告或开始连接。关闭未确认提示必须保留，不能用新目标绕过。报告只证明识别，不是收发/运动验收。

## 明确输出测试

1. 只对自己的安全测试接收端操作。波特率必须与接收端一致（默认115200）；8N1/no-handshake，DTR/RTS开关可能复位板卡。ROM0x30之外以及未知描述符预期拒绝。
2. 明确Connect后只显示已打开/未启用发送，无轴命令。开始合法媒体或显式预览，再明确Arm，检查接收端收到TCode；本地写次数不能证明外接设备执行。不得用CH输入按钮/轴手势当本版本功能，IN未实现。
3. 分别测fixed/polled、dirtyOnly、反向range、Stop、后台、断连/拔出；每次重新连接都应保持disarmed。记录接收字节与界面状态，不能要求未确认关闭自动重试。
4. 添加第二serial目标：已有真实serial打开时应拒绝第二个，不关闭第一个。确认第一个关闭后才可显式连第二个。网络多目标仍独立。
5. PC系统26授权在open内等待真实结果；19需明确将DTR/RTS都选系统管理。phone/tablet通常无这两个syscap，请勿据空列表宣称已支持。CDC与其他vendor芯片未开放。

检查手机横竖/平板/PC的串口下拉、长名字换行、52vp控件、报告可滚动/复制、固定Stop可达、视频单Surface保持。没有新的截图或视觉渲染证据；具体HMOS工坊参考仍未知。
