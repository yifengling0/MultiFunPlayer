# 0.31 播放交互与设备验收边界

本版本修复 0.30 没有浮窗拖动、画面点击只处理控制条、显示播放状态取自输出门控的问题。视频图像层、手势层和按钮层分别布局；按钮容器使用允许子控件命中的 Default，只有画面输入层拦截背后内容。原生 AVPlayer 事件提供视频时间与播放状态；暂停输出门控不能伪造视频暂停。

## 操作
- 点画面直接暂停或继续。点明确的播放/暂停按钮执行同一动作，按钮不会再触发画面点击。自然结束后点重播，等待确认的 seek 完成后恢复。
- 首页/控制页滚动后出现浮窗。拖动画面超过 8vp 移动；松手不会切换播放。位置限制在当前窗口可见区，旋转/尺寸变化后重新约束。
- 浮窗底部提供暂停/播放和展开。展开回到大预览；全屏另用大预览按钮。窗口切换不重开视频或自动 Arm。
- 全屏默认隐藏系统栏；暂停时显示控制。播放中的控制自动隐藏，点画面暂停并显示。停止、后台和失焦仍执行安全停机。
- 准备/加载中不启动；原生尚有播放意图时允许安全暂停。错误需要先处理错误，不能通过点击绕开故障。快速连续点击不会同时发出重复原生命令。

## 本地可复现测试
运行 node --test tests/*.test.mjs。video-composition-031.test.mjs 执行官方 SDK 编译后的真实 videoStage builder 与事件绑定，验证单 Surface、输入/按钮兄弟层级、按钮祖先不屏蔽子控件、浮窗/全屏尺寸。它使用记录型 ArkUI API，不能替代系统命中测试和渲染。

visual-lab 复用生产几何和命令/拖动模块，提供真实 HTML video 的独立适配环境；见该目录 README。浏览器适配不是 ArkUI 渲染器。
